# Issue #56 — [ApiTests][T3] `config/env.ts` — zod-загрузчик окружения

> **Режим:** test-authoring / инфраструктура фреймворка (метки `api`, `testing`).
> Production-код `AddressBook.Api` / `AddressBook.Web` **не трогаем**.
> **Родительский план:** [docs/tasks/api-tests-framework-plan.md](api-tests-framework-plan.md) — задача **T3**.
> **Зависит от:** T2 (зависимости `zod`, `dotenv` уже в `main`).

## 1. Требование

Реализовать типобезопасную загрузку конфигурации окружения через `zod` + `dotenv`:
единая точка чтения `BASE_URL` и таймаутов с валидацией при импорте и понятной ошибкой
при некорректных данных. Модуль станет источником истины для остального фреймворка (клиенты,
фикстуры, конфиг Playwright).

## 2. Критерии приёмки

| # | Критерий | Как проверяется |
|---|----------|-----------------|
| A1 | Некорректные/отсутствующие переменные → явная ошибка валидации | Юнит-проверкой: подать невалидный `BASE_URL` / отрицательный таймаут → `parse` бросает читаемую ошибку со списком полей. Проверяется `npx tsx` / временным прогоном. |
| A2 | Экспортируется типизированный объект `env` | `env` имеет тип, выведенный из zod-схемы (`z.infer`); поля `baseURL: string`, `apiTimeout: number`, `expectTimeout: number` доступны с автодополнением. |
| A3 | Значения по умолчанию | Без `.env.local` `BASE_URL` = `http://localhost:5000/api/`, таймауты = значения из `.env.example`. |
| A4 | `npm run lint` + типизация чистые | `eslint .` и `tsc --noEmit` без ошибок. |

| Файл | Изменение |

## 4. Подход

Порядок: **env.ts → wiring config → верификация**.

1. **`src/config/env.ts`:**
   - Загрузка `dotenv`: `.env.local` всегда; в CI дополнительно `.env.ci` (если присутствует).
     Порядок: сначала `.env.ci` (CI), затем `.env.local` — локальные значения имеют приоритет
     на dev-машине; в CI `.env.local` обычно отсутствует.
   - zod-схема:
     - `BASE_URL`: `z.string().url()` + `.refine(v => v.endsWith('/'))` (нужно для корректного
       разрешения относительных путей `new URL('Contacts', baseURL)`), `.default('http://localhost:5000/api/')`.
     - `API_TIMEOUT`: `z.coerce.number().int().positive().default(30000)`.
     - `EXPECT_TIMEOUT`: `z.coerce.number().int().positive().default(5000)`.
   - `safeParse(process.env)`; при `!success` — собрать сообщение из `error.issues`
     (`path` + `message`) и бросить `Error` с понятным текстом.
   - Экспортировать `env` (camelCase-объект) и тип `Env = z.infer<typeof schema>`.
2. **`playwright.config.ts`:** импортировать `env`, использовать `env.baseURL` для `use.baseURL`
   и readiness-URL. dotenv-загрузку перенести в `env.ts` (убрать дублирующий `dotenv.config`
   из конфига), чтобы окружение грузилось в одном месте.
3. **Верификация:** `tsc --noEmit`, `npm run lint`, точечная проверка ошибки валидации.

### Решения

- **Трейлинг-слэш в `BASE_URL`.** `.env.example` уже требует `/api/` на конце; refine делает это
  требование машинно-проверяемым и предотвращает молчаливую потерю сегмента `api` при
  `new URL(relative, base)`.
- **`z.coerce.number`** — переменные окружения всегда строки; coerce даёт число из `"30000"`.
- **Единый источник.** Правка `playwright.config.ts` — не расширение объёма, а устранение
  дублирования чтения env, появившегося в T2.

## 5. Tests (Playwright E2E)

Новых Playwright-спеков в T3 **нет** — это инфраструктурный модуль без API-поведения.
Корректность покрывается критериями A1–A3 (валидация/дефолты) и компиляцией типов.
Полноценные E2E-спеки добавляются в T10–T16 и будут потреблять `env` косвенно через клиенты.

## 6. Вне объёма

- `.env.ci` как файл не создаём (поддержку загрузки добавляем, сам файл — при настройке CI, T18).

## 7. Верификация

1. `npx tsc --noEmit` в `src/ApiTests` — без ошибок типов.
2. `npm run lint` — без ошибок.
3. Точечная проверка: импорт `env` с валидным окружением возвращает дефолты; подстановка
   невалидного `BASE_URL` / отрицательного таймаута бросает читаемую ошибку.
4. `npx playwright test --list` — конфиг по-прежнему загружается (регрессия wiring).
